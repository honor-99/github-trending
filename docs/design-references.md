# 竞品与设计参照（2026-11-12 调研）

目的：在决定"榜单页长什么样"之前，先看同类站点实际怎么做的。
所有数字是当天用无头 Chrome 在 1440×1100 下**实测 computed style**，不是印象。

## 一、同类站点实测

| 站点 | 底色 | 正文字体 | H1 | 主列表行高 | 结构 | 图标数 |
|---|---|---|---|---|---|---|
| github.com/trending | `#ffffff`(浅) / `#0d1117`(深) | Mona Sans VF / system，14px | **32px / 600** | **150px**（每条 repo 一块） | 无表格、无卡片，纯列表 + 语言色点 + "2,776 stars today" + 贡献者头像 | 109 |
| ossinsight.io/trending | `#1a1a1b` 深色优先 | system-ui，16px | 30px / **700**（带 🔥） | **39px**（密排行） | 分页表格感，Tab 切换数据维度 | 4 |
| star-history.com | 深色底 | Figtree，16px | 无 H1（直接进榜） | **28px**（最密） | 榜单：名次 + 头像 + 项目 + `+24,468` 差值 + ▲▼ 箭头 | 11 |
| hellogithub.com | `#f3f4f6` 浅灰 | system-ui，16px | 无 H1（用 hero 图） | 48px | 杂志式卡片 + 项目截图，内容 1280px 居中 | 38 |
| trendshift.io | `#ffffff` | Instrument Sans，16px | 24px / 600 | 63–82px | 日/周/月 tab + 行内 logo + 名次变化，超长页（5934px） | 199 |

**共同点（可直接抄的规律）**

1. **H1 都不大**：24–32px。没有一个用 40px+ 大标题，页面重心直接给榜单。
2. **主列表是"行"，不是"卡片"**：28–83px 一行（HelloGitHub 是唯一的卡片派，因为它是图文杂志）。
3. **行内三层信息**：名次 / 项目名 + 一句话描述 / 右侧数字（今日新增 star、差值、热度）。
4. **必须有"变化量"**：GitHub 写 `stars today`，Star History 写 `+24,468 ▲`，Trendshift 标名次涨跌。
   只有总数没有差值，读者判断不了"今天发生了什么"。
5. **视觉锚点靠色点/头像，不靠装饰**：语言色点（GitHub/Trendshift）、项目 logo、贡献者头像。
6. **深色是这类工具站的主流**：5 家里 3 家深色优先，2 家纯白。

**各自的短板（我们不要学）**

- GitHub Trending：一屏只放得下 4–5 条，滚动力差；没有 KPI 概览。
- OSSInsight：D3 生态重，UI 偏"数据工程"味，中文文案稀薄。
- Star History：28px 行太密，没有描述，只能看"涨了多少"，看不懂"是什么"。
- HelloGitHub：卡片 + 截图 = 一屏 2 条，适合杂志不适合每日扫榜。
- Trendshift：单页 5900px，行内 icon 太多（199 个 svg），信息噪音大。

## 二、设计系统参照（来自 popular-web-designs 模板）

| 参照 | 语言 | 适配度 | 用在哪 |
|---|---|---|---|
| **Linear** | 近黑 `#08090a` + 半透明白描边 + 单一靛紫 `#5e6ad2`，亮度递进做层级，字重 400/510/590 | ★★★★☆ | 就是当前 `linear` 皮肤；最适合"工程感 + 密排" |
| **Vercel** | 纯黑/纯白 + Geist + 6px 圆角 + 几乎无色 | ★★★★☆ | 想要更硬朗、更"发布页"的克制感 |
| **Sentry** | 深色数据密集 + 语言/状态色 + 微图表 | ★★★★ | 想把"趋势"讲清楚（sparkline、增量条） |
| **Stripe** | 白底 + Source Sans 300 + 紫蓝渐变（只用一处） | ★★★ | 想要更柔和、更"成品感" |

## 三、我们缺的东西（对照竞品）

1. **没有 sparkline / 历史曲线**：竞品里 Star History、OSSInsight 都有"这段时间怎么涨"的可视化，我们只有单期数字。
2. **差值表达弱**：现在只有 `+1,234 ★` 文字 + 42px 细条，Star History 的 `▲/▼` + 大号差值更容易扫。
3. **排名变化没体现**：我们有新上榜/持续/掉榜三块，但没有"名次 ↑3"这种行内信号。
4. **视觉锚点不足**：没有项目 logo/头像，全靠文字，长列表里找项目靠读名字。

## 四、三个可落地方向

### A. 密排工程派（Linear 深化，当前方向）
- 行高压到 72–80px，描述 clamp 到 1 行（首条 2 行）
- 右侧改为"差值数字 + ▲▼"，名次列带 `↑3` 小标
- 语言色点放大到 8px 并带项目首字母方块做锚点
- 风险：信息密度上去了，但少了"看点"

### B. 数据可视化派（Sentry / OSSInsight 借鉴）
- 每个条目右侧加 40×16 的 sparkline（需要抓历史 star 快照，我们已有 4 期 archive 可用）
- KPI 条加"本期总量"迷你柱状图
- 风险：要写 SVG 生成逻辑，数据点太少（4 期）时曲线意义有限

### C. 榜单仪式感派（Star History / Trendshift 借鉴）
- 名次大字（28–32px mono）+ 头像/logo 圆形 + 差值胶囊
- 榜单首三名给一点强调（左侧竖细线或浅底）
- 风险：容易滑向 "product hunt 风"，和"归档工具"的冷静气质相悖

## 五、我的建议

**A 为主 + B 的一个小切片**：先把行密度、差值表达、名次变化做进去（纯 CSS + 已有数据），
sparkline 等 archive 攒够 8 期以上再加。理由：现在最"丑"的不是配色，是**行内信息组织方式**
—— 项目名 + 两行灰描述 + 一排小标签，读起来像博客列表而不是榜单。
